# Hormachuelos Optimized 1.3.0

## AGENTIC Workbench

This optional feature release adds a separate **AGENTIC** mode without replacing Adaptive or changing the default mode.

### Adaptive Director

- AGENTIC scopes each request through Ask, Plan, Research, Multi-Agent, and Build, skipping phases that do not add value.
- Straightforward questions remain read-only and can finish in Ask.
- Plan-only and research-only requests never enter Build.
- Clear implementation requests may enter Build immediately; destructive and outside-project actions keep their existing confirmations.
- The selected mode remains AGENTIC while the Workbench shows the active internal phase.

### Real evidence workers, one writer

- The Director creates two or three isolated model workers only when the request has genuinely independent evidence workstreams.
- Workers use the selected provider, model, and effort. Hormachuelos does not silently substitute another model.
- Native workers can overlap under a host-wide three-worker semaphore. Cursor workers use separate ephemeral Cursor agents and report the bridge's serial limitation honestly.
- Every worker is read-only at both schema and execution time. Workers cannot edit files, run commands, control apps, connect accounts, ask questions, request approval, or complete the parent turn.
- One Director owns mutation, integration, repair, verification, and delivery.
- Cancellation reaches queued and active workers, interrupts model/tool waits, seals worker cards, and ignores late results.
- Worker findings and public web output are treated as untrusted evidence and credential-redacted before events, persistence, or Director synthesis.

### Execution Workbench

- AGENTIC turns use one Workbench with a phase strip and separate Progress, Tools, and Agents lanes.
- Progress contains bounded public phase updates and evidence, never private provider chain-of-thought.
- Tool cards show queued, running, passed, failed, and cancelled state with owner, phase, sanitized arguments, and bounded results.
- A pinned Director card and up to three worker cards show assignments, state, usage, tools, and final contributions.
- Agent selection filters the Tools lane.
- Wide layouts show all three lanes; narrower layouts use keyboard-accessible tabs; the 390px mobile layout has no page-level horizontal overflow.
- Clearline Markdown answers remain full-width below the Workbench with dividers, bold hierarchy, lists, code blocks, file chips, Copy reply, and feedback actions.

### Delivery Board

- Terminal runs collapse live execution behind **Inspect run** and lead with Outcome, Changes, Verification, Agent Contributions, Risks & Next Actions, and Run facts.
- Verification passes only when a host-observed tool reports concrete success.
- Read-only runs omit Changes.
- Failed workers, failed checks, missing verification, and cancellation produce honest Partial, Needs attention, or Cancelled outcomes.
- Existing Review changes, Time Machine, Export Client Pack, Copy reply, and feedback actions remain available where applicable.

### Compatibility and persistence

- Existing Ask, Research, Plan, Build, Parallel, and Adaptive behavior remains unchanged.
- AGENTIC phase, worker, tool ownership, completion evidence, and aggregate usage replay as one Workbench in restored sessions.
- Pre-1.3.0 sessions retain the existing Thought → Tools → Answer renderer.
- Cursor parent agent IDs remain resumable; ephemeral worker provider IDs are never persisted.

### Remote verification

- Deterministic AGENTIC routing, permission, decomposition, cancellation, concurrency, delivery-honesty, persistence, and Cursor ownership tests
- TypeScript, production Vite build, FPS, Preview Computer Use, Ask-mode, reply-formatting, Cursor lifecycle, Rust formatting, and Windows native tests
- Playwright coverage for live, simple, successful, partial, cancelled, and unverified Workbenches
- Desktop, 820px narrow, and 390px mobile evidence with keyboard, focus restoration, reduced-motion, filtering, replay-safe completion, and no horizontal overflow

This release is published as an optional feature update.
